# 開発ガイド

処理系は Rust と Parol で実装し、C++20 を生成します。最初の段階では、整数の入出力と値の共有・コピーを出発点に、比較・条件分岐・ループまで動かせます。

## 構成

| ファイル | 役割 |
|---|---|
| `rusk.par` | Parol の文法 |
| `build.rs` | パーサーを `OUT_DIR` に生成 |
| `src/rusk_grammar.rs` | 生成パーサーから構文木を受け取る |
| `src/ast.rs` | ソース位置を持つ AST への変換 |
| `src/compiler.rs` | 名前・型・初期化の検査、糖衣構文の展開、C++生成 |
| `lib/core.rusk` | 基本型・演算・入出力・C++ランタイムの定義 |
| `tests/e2e.rs` | Rusk → C++ → 実行結果までのテスト |

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

テストには `g++` が必要です。生成コードを最適化付きでコンパイルし、共有とコピー、評価順序、整数の境界値、診断などを確認します。

## C++の実装をRusk側に置く

外部型・関数の宣言はトップレベルに置きます。プロパティは JSON 形式の文字列で、末尾のカンマが必要です。以下は暫定的な外部実装インターフェースです。

```text
extern type Int {
    cpp_name: "std::int64_t",
}
extern fn __add__(a: Int, b: Int) -> Int {
    cpp_name: "rusk_add_int",
    code: "Obj<std::int64_t> rusk_add_int(Obj<std::int64_t> a, Obj<std::int64_t> b, Loc loc) { return make_obj<std::int64_t>(checked_int(static_cast<__int128>(*a) + *b, loc)); }",
}
```

これは標準ライブラリから抜粋した例で、利用プログラムに再定義する必要はありません。`extern symbol 名前 { code: "...", }` は共通コードを出力します。現在はすべての symbol と、直接使われた外部関数のコードを定義順に出力します。symbol 間は名前順です。外部関数間の依存解決はまだないため、相互参照には symbol 内の前方宣言などが必要です。

ABI は引数と戻り値を `Obj<T>`（現在は `std::shared_ptr<T>`）で渡し、末尾にエラー位置の `Loc` を受け取ります。戻り型省略時は C++側を `void` にします。外部関数には正しい C++ と共有・コピーの契約を守る責任があります。

関数は名前と引数型で選びます。現時点では完全一致だけで、戻り値による選択は `in` のための `__read__` のみです。外部宣言自体は先に登録するため、ソース上の使用箇所より後にも書けます。

## 暫定実装と設計の区別

共有ポインターは意味論の検証用です。基本型を含む全ての値をヒープに置くため、現段階で実行速度の目標を達成したとは扱いません。今後、共有が観測されない値の実体化を省く最適化などを検討します。整数の検査は GCC/Clang の `__int128` を使います。

現在は AST から直接 C++ を生成します。機能が増える段階で型付きの中間表現を分けることを検討します。LLVM、ユーザー定義関数、ジェネリクス、配列、`for` はまだ実装していません。条件の暗黙変換は暫定の `__bool__` フックを使います。

設計の思想・理由・保留事項は `design/`、実装済みの説明は `docs/` に残します。ドキュメントの編集方法は [編集と公開](documentation.md) を参照してください。
